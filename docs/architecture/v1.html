rate_limitar · production layout

Three app servers, one shared Valkey, no single box that takes it all down

Server A stays an app-only primary with double weight. The load balancer, Valkey and MongoDB are rented managed services, so none of them uses your servers' RAM, and each runs with its own redundancy.

How the breaker decides

If one piece fails

FailsAppWhat happens
Server A up Load balancer sees /health fail and sends all traffic to B and C. Slower, not down.
Server B or C up Same: the other two keep serving.
Valkey primary up Provider promotes the replica in seconds. Meanwhile requests are allowed (today) or limited per server (with the breaker).
All of Valkey degraded API keeps working. Rate limits are off (today) or per server, up to 3× (with the breaker). Cache misses go to MongoDB.
MongoDB primary up Atlas elects a new primary within seconds; writes pause briefly, and cached reads still come from Valkey.
Load balancer machine up Provider runs it on several machines and replaces the failed one.
Whole provider region down The one remaining risk. Surviving it needs a second region with DNS failover, usually not worth it at this size.
